# RetroPong for the web

A static web port of RetroPong. The connection screen is the only web-specific
step. After connecting, the game uses the desktop Rust simulation, palette,
menu, bitmap font, settings, countdown and launch hints, plus the desktop CRT
shader and synthesised sounds. No server-side game process is required.

From the repository root:

```sh
rustup target add wasm32-unknown-unknown
sh game/superpong-web/build.sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory game/superpong-web/public
```

Open <http://127.0.0.1:8080>. Plug in the RetroController and turn a knob.
Browsers may wait for movement or a page interaction before exposing a gamepad.
In Chrome/Edge, clicking the connection screen opens a WebHID permission chooser; already
granted devices reconnect automatically. The native font and palette also supply the connection screen.

The native power-on screen appears after loading. **Enter** starts/restarts,
**Escape** opens/closes the native menu, arrows navigate, and Enter selects.
The gamepad Start button opens the menu; its D-pad navigates, South selects,
and East closes. The RetroController's own optional buttons also drive the
menu: left opens it and selects, right moves to the next entry and wraps. Both knobs retain the same direction and full travel as the
controller's native HID readings. Disconnecting pauses play; reconnecting returns
to the native menu so you can resume with the usual countdown.

The page never requests or exits fullscreen and does not capture the keyboard.
Use the browser's own window/fullscreen controls. Click the game or press Enter
to unlock sound. On browsers that reserve Escape in browser-managed fullscreen,
the browser controls that key.

The connection screen is static, with larger native RETROPONG lettering and two
prompt lines: “CONNECT CONTROLLER” and “& TURN KNOB”. It has no scores or game
animation. Clicking
that screen opens the USB chooser when needed. There is no other page text or
HTML game interface. Exit Game returns to this same screen; turn a knob or click
to play again. The small WASM core loads on page entry to draw the splash.

Game mode, colour, CRT, volume and each knob’s direction are saved in this
browser and restored on reload or replay. The native menu selects CW UP (the default) or CCW UP
for each knob. Storage is optional: blocked storage or invalid saved data uses
defaults without interrupting play. Physical left/right assignment belongs to the
controller firmware.

To deploy, serve the **contents of `public/` after building** from any static
HTTPS host. HTTPS (or localhost) is required for controller APIs. Generated WASM,
shader and sound files are ignored in Git and regenerated by `build.sh`. The
build exports the native sounds, so native game build dependencies are needed
at build time; visitors need only a browser. No package installation is needed.

Verification:

```sh
cargo test -p superpong-web -p superpong-core
node --test game/superpong-web/tests/*.test.mjs
```

The WebAssembly wrapper imports the desktop UI modules directly and runs their
existing tests, including the menu's golden raster. Additional tests cover the
web ABI, controller mapping and lifecycle, audio and the splash render.
